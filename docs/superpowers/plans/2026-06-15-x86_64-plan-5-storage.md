# x86_64 Plan 5 — Storage (ATA/ext) na 64-bit + boot z dysku

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Postawić stos pamięci masowej na 64-bicie. Warstwy MI (`Vfs`, `ExtFilesystem`
ext2/ext4 read+write, `DeviceManager`, `RamBlockDevice`, `BlockCache`/`ExtAllocator`/`Journal`)
są **maszynowo-niezależne i host-testowane** — nie tykamy ich. Robota MD jest mała: przenieść
`ATA.S` na elf64 (port I/O jest w long mode IDENTYCZNE; jedyna realna zmiana to 64-bitowe
rejestry adresu bufora dla `rep insw`/`rep outsw` oraz wejścia cdecl→System V AMD64), dodać
`block_x86_64.cpp` implementujący kontrakt `<arch/block.h>` (`bootDisk`) i cienki glue
`Hdd64`/`AtaBlockDevice64`. Potem **od-stage'ować jądro**: stage'owany w Planie 2 kernel
x86_64 dostaje prawdziwy `arch::bootDisk()`, więc MI `Kernel::start` montuje `/disks/main` z
**obrazu dyskowego GRUB** (nie z rescue-ISO) i czyta/zapisuje plik. Wykrywanie partycji z MBR
(kernel już to robi w `firstPartitionLba`) zostaje bez zmian.

**Architecture:** Migracja-zastąpienie (patrz `docs/superpowers/specs/2026-06-15-x86_64-migration-analysis.md`,
§2.4, §7 kamień 5, §4). `arch/x86_64/drivers/` zawiera kompletny, samodzielny zestaw MD storage:
`ATA64.S` (jedyny plik z realnymi zmianami), `Hdd64.{h,cpp}`, `AtaBlockDevice64.{h,cpp}`,
`block_x86_64.cpp`. Granica MI/MD jest nienaruszona: interfejs `BlockDevice` (HAL),
`AtaBlockDevice`-owa pętla „jedna komenda na sektor", `DeviceManager`, `Vfs` i rdzeń `ext` są
te same co na i686 — kompilują się jedynie nowym toolchainem `x86_64-elf`. `Kernel.cpp` (MI)
**nie wymaga żadnej edycji** — całe okablowanie storage (`bootDisk → DeviceManager → mount →
extRwSelftest`) już tam jest; Plan 5 dostarcza tylko realną implementację `arch::bootDisk()`.

**Tech Stack:** `x86_64-elf-` cross-toolchain (z Planu 1), NASM `-f elf64`, GNU ld, GRUB2
i386-pc (multiboot1 ładuje obraz ELF64 — patrz Plan 1), `qemu-system-x86_64 -drive
file=disk/image-grub2.img,format=raw`, `e2fsprogs` w kontenerze `nanos-build`. Stos ATA to
PIO (polling DRQ), więc **nie zależy od przerwań** — działa nawet przy minimalnym IDT.

**Zależności (handoff z Planów 2–4):**
- **Plan 2** doprowadził `ARCH=x86_64 make _all` do **pełnego linku elf64 `bin/kernel.bin`** z
  `MI_SOURCES` + x86_64 `ARCH_SOURCES` (loader64.o/entry64.o + console/multiboot), a MI
  `Kernel::start` jest wykonywany aż do pętli idle. Żeby zlinkować referencję `arch::bootDisk()`
  z MI `Kernel.cpp`, Plan 2 dostarczył **tymczasowy stub** `arch/x86_64/drivers/block_stub.cpp`
  zwracający wyzerowany `RamBlockDevice` (montaż pustego ramdysku zawodził łagodnie, log) i
  wpisał `block_stub.o` do x86_64 `ARCH_SOURCES`. **Plan 5 ten stub usuwa.**
- **Plan 3** dał paging 4-poziomowy (kernel mapuje RAM, bufory ATA leżą w identity/low-canonical).
- **Plan 4** dał GDT/IDT/TSS + ścieżkę przerwań (kernel nie triple-faultuje; PIO nie potrzebuje
  IRQ, ale `Kernel::start` musi dożyć do okablowania storage).

> Jeśli faktyczny stan z Planów 2–4 różni się detalem (np. inna nazwa stuba albo guard
> `#ifdef` zamiast osobnego pliku), Task 3 jest miejscem, w którym to się uzgadnia —
> niezmienny cel: po Tasku 3 jedynym dostawcą `arch::bootDisk()` dla x86_64 jest
> `block_x86_64.cpp`, a stub znika z linku.

**Kontrakt nazewniczy (spójny z Planami 1–4, 6–8):** katalog `arch/x86_64/drivers/`; prefiks
toolchaina `x86_64-elf-`; NASM `-f elf64`. **Kolizje nazw obiektów w współdzielonym `bin/`**
(elf32 i686 vs elf64 x86_64 nie linkują się razem) rozwiązujemy sufiksem `64` lub odrębną bazą
nazwy: `ATA.S → ATA64.o`, `Hdd.cpp → Hdd64.o`, `AtaBlockDevice.cpp → AtaBlockDevice64.o`,
`block_x86.cpp → block_x86_64.o`. Wszystkie wylistowane w `arch/x86_64/arch.mk` `ARCH_SOURCES`.
`AtaBlockDevice` **wydaje jedną komendę ATA na sektor** (kwirk z i686: `rep insw` na >1 sektor
desynchronizuje napęd) — zachowane na 64-bicie. `BlockDevice::readSectors(unsigned lba,…)`
zostaje `unsigned` (pełny sweep LP64 to Plan 7 — tu minimalnie/addytywnie).

## Task 1: Port `ATA.S` → `arch/x86_64/drivers/ATA64.S`

To jedyny plik storage z realnymi zmianami. Port I/O (`in`/`out`) jest w long mode
identyczne; zmieniają się tylko (1) rejestr adresu bufora na 64-bitowy (`rep insw` używa
`[RDI]`, `rep outsw` używa `[RSI]` w trybie 64-bit), (2) `pushf/popf` → `pushfq/popfq` i
64-bitowe push/pop, (3) wrappery cdecl (args ze stosu) → System V AMD64 (args w
`RDI/RSI/RDX`). LBA jest 28-bitowe, więc dalej mieści się w rejestrze 32-bitowym (`EAX`/`EBX`).

**Files:**
- Create: `arch/x86_64/drivers/ATA64.S`

- [ ] **Step 1: Napisać `arch/x86_64/drivers/ATA64.S`**

```nasm
;=============================================================================
; arch/x86_64/drivers/ATA64.S — ATA PIO read/write (LBA28), long-mode port.
;
; Port I/O (in/out) is IDENTICAL in long mode. The only real changes vs the
; i686 arch/x86/drivers/ATA.S are:
;   (1) the data buffer pointer is a 64-bit register — RDI on the read path,
;       RSI on the write path — because `rep insw`/`rep outsw` use ES:[RDI] /
;       DS:[RSI] with 64-bit address size in long mode;
;   (2) flags + saved regs are pushed 64-bit (pushfq / push rbx ...);
;   (3) the cdecl stack-arg wrappers become System V AMD64 register-arg
;       wrappers: lba in EDI, sect_count in SIL, buf in RDX.
; LBA is 28-bit so it still lives in a 32-bit register (EAX/EBX). The caller
; (AtaBlockDevice64) issues ONE command per sector — the i686 `rep insw`
; multi-sector desync quirk is unchanged in long mode.
;=============================================================================

bits 64
section .text

;-----------------------------------------------------------------------------
; ata_lba_read — internal.
;   EAX = LBA (28-bit), CL = sector count, RDI = destination buffer.
;   returns EAX = 0 on success, 1 on error (ERR/DF set, or DRQ timed out).
;   NOTE: EAX is NOT preserved — LBA in, status out.
;-----------------------------------------------------------------------------
ata_lba_read:
               pushfq
               push rbx
               push rcx
               push rdx
               push rdi
               push rsi

               mov ebx, eax         ; save LBA in EBX (28-bit, fits 32)

               mov edx, 0x01F6      ; drive / LBA bits 24-27
               shr eax, 24
               or  al, 11100000b    ; LBA mode, master
               out dx, al

               mov edx, 0x01F2      ; sector count
               mov al, cl
               out dx, al

               mov edx, 0x1F3       ; LBA bits 0-7
               mov eax, ebx
               out dx, al

               mov edx, 0x1F4       ; LBA bits 8-15
               mov eax, ebx
               shr eax, 8
               out dx, al

               mov edx, 0x1F5       ; LBA bits 16-23
               mov eax, ebx
               shr eax, 16
               out dx, al

               mov edx, 0x1F7       ; command port
               mov al, 0x20         ; READ SECTORS (with retry)
               out dx, al

               mov esi, 0x100000    ; DRQ spin timeout (RSI is free on the read path)
.rd_wait:      in  al, dx           ; status register (0x1F7)
               test al, 0x21        ; ERR (bit0) or DF (bit5) -> the command failed
               jnz .rd_err
               test al, 8           ; DRQ (bit3) -> sector buffer ready
               jnz .rd_ready
               dec esi
               jnz .rd_wait
               jmp .rd_err          ; timed out waiting for DRQ

.rd_ready:     mov eax, 256         ; 256 words = 1 sector
               xor bx, bx
               mov bl, cl
               mul bx               ; DX:AX = 256 * count (count==1 -> 256)
               mov ecx, eax         ; rep counter (zero-extends into RCX)
               mov edx, 0x1F0       ; data port
               rep insw             ; words -> ES:[RDI]; RDI is the 64-bit buffer
               xor eax, eax         ; success -> 0
               jmp .rd_done
.rd_err:       mov eax, 1           ; error -> 1
.rd_done:
               pop rsi
               pop rdi
               pop rdx
               pop rcx
               pop rbx
               popfq
               ret

;-----------------------------------------------------------------------------
; ata_lba_write — internal.
;   EAX = LBA (28-bit), CL = sector count, RSI = source buffer.
;   returns EAX = 0 on success, 1 on error.
;-----------------------------------------------------------------------------
ata_lba_write:
               pushfq
               push rbx
               push rcx
               push rdx
               push rsi
               push rdi

               mov ebx, eax         ; save LBA in EBX

               mov edx, 0x01F6      ; drive / LBA bits 24-27
               shr eax, 24
               or  al, 11100000b
               out dx, al

               mov edx, 0x01F2      ; sector count
               mov al, cl
               out dx, al

               mov edx, 0x1F3       ; LBA bits 0-7
               mov eax, ebx
               out dx, al

               mov edx, 0x1F4       ; LBA bits 8-15
               mov eax, ebx
               shr eax, 8
               out dx, al

               mov edx, 0x1F5       ; LBA bits 16-23
               mov eax, ebx
               shr eax, 16
               out dx, al

               mov edx, 0x1F7       ; command port
               mov al, 0x30         ; WRITE SECTORS (with retry)
               out dx, al

               mov edi, 0x100000    ; DRQ spin timeout (EDI is free on the write path)
.wr_wait:      in  al, dx           ; status register (0x1F7)
               test al, 0x21        ; ERR or DF -> failed
               jnz .wr_err
               test al, 8           ; DRQ -> ready for the data
               jnz .wr_ready
               dec edi
               jnz .wr_wait
               jmp .wr_err

.wr_ready:     mov eax, 256         ; 256 words = 1 sector
               xor bx, bx
               mov bl, cl
               mul bx
               mov ecx, eax         ; rep counter
               mov edx, 0x1F0       ; data port
               rep outsw            ; words from DS:[RSI]; RSI is the 64-bit buffer
               ; The drive is BSY committing the sector. Wait for it to clear before the
               ; next command, or back-to-back single-sector writes race the busy drive.
               mov edx, 0x1F7
               mov edi, 0x100000
.wr_drain:     in  al, dx
               test al, 0x21        ; ERR or DF -> failed
               jnz .wr_err
               test al, 0x80        ; BSY still set?
               jz  .wr_flush
               dec edi
               jnz .wr_drain
               jmp .wr_err
               ; FLUSH CACHE: force the write to the medium so it survives reboot/power loss.
.wr_flush:     mov al, 0xE7
               out dx, al
               mov edi, 0x100000
.wr_fwait:     in  al, dx
               test al, 0x80        ; BSY clear after the flush?
               jz  .wr_ok
               dec edi
               jnz .wr_fwait
.wr_ok:        xor eax, eax         ; success -> 0
               jmp .wr_done
.wr_err:       mov eax, 1           ; error -> 1
.wr_done:
               pop rdi
               pop rsi
               pop rdx
               pop rcx
               pop rbx
               popfq
               ret

;=============================================================================
; extern "C" int read_ata_pio(int lba, char sect_count, char* buf);
;   System V AMD64: lba in EDI, sect_count in SIL, buf in RDX. Returns EAX.
;=============================================================================
global read_ata_pio
read_ata_pio:
               push rbp
               mov  rbp, rsp
               mov  eax, edi        ; LBA (read before clobbering RDI)
               mov  cl,  sil        ; sector count
               mov  rdi, rdx        ; destination buffer (full 64-bit pointer)
               call ata_lba_read    ; EAX = status (0 ok, 1 error)
               pop  rbp
               ret                  ; status in EAX

;=============================================================================
; extern "C" int write_ata_pio(int lba, char sect_count, char* buf);
;   System V AMD64: lba in EDI, sect_count in SIL, buf in RDX. Returns EAX.
;=============================================================================
global write_ata_pio
write_ata_pio:
               push rbp
               mov  rbp, rsp
               mov  eax, edi        ; LBA
               mov  cl,  sil        ; sector count (read SIL before clobbering RSI)
               mov  rsi, rdx        ; source buffer (RSI for rep outsw)
               call ata_lba_write   ; EAX = status
               pop  rbp
               ret
```

/*
 * Hdd64.h — x86_64 ATA PIO forwarder (mirror of arch/x86/drivers/Hdd.h).
 * The extern "C" routines live in ATA64.S. Distinct object name (Hdd64.o) so the
 * elf64 object never collides with the i686 Hdd.o in the shared bin/.

#pragma once

namespace kernel {

// Return 0 on success, non-zero if the drive reported an error (ERR/DF) or DRQ timed out.
extern "C" int read_ata_pio(int lba, char sect_count, char* buf);
extern "C" int write_ata_pio(int lba, char sect_count, char* buf);

class Hdd {
public:
	static int readSectors(int lba, char count, char* buf);    // 0 ok, non-zero I/O error
	static int writeSectors(int lba, char count, char* buf);
};

} /* namespace kernel */

- [ ] **Step 4: `arch/x86_64/drivers/AtaBlockDevice64.cpp`**

```cpp
#include "AtaBlockDevice64.h"
#include "Hdd64.h"

namespace kernel {

AtaBlockDevice::AtaBlockDevice(const char* name) {
	this->devName = name;
}

// Issue ONE ATA command per sector. The PIO routine in ATA64.S polls DRQ only once
// per command and then transfers count*256 words; for count > 1 that desyncs the drive
// (the data buffer must be re-serviced per sector), which corrupts this and subsequent
// transfers. One sector per command keeps it correct — identical to the i686 driver.
int AtaBlockDevice::readSectors(unsigned lba, unsigned count, void* buf) {
	char* p = (char*) buf;
	for (unsigned i = 0; i < count; i++)
		if (Hdd::readSectors((int) (lba + i), 1, p + i * 512) != 0)
			return -5;   // -EIO: the drive flagged an error (don't return silent garbage)
	return 0;
}

int AtaBlockDevice::writeSectors(unsigned lba, unsigned count, const void* buf) {
	char* p = (char*) buf;
	for (unsigned i = 0; i < count; i++)
		if (Hdd::writeSectors((int) (lba + i), 1, p + i * 512) != 0)
			return -5;   // -EIO
	return 0;
}

unsigned AtaBlockDevice::sectorSize() {
	return 512;
}

const char* AtaBlockDevice::name() {
	return devName;
}

}
```

## Self-Review

- **Spec coverage:** Plan realizuje kamień 5 z §7 specu („Storage: ATA.S→64-bit (drobne), boot
  z ext4 — odtworzenie funkcjonalności read/write, e2fsck-clean"). §2.4 potwierdza, że `ATA.S`
  to „najmniej dotknięty plik asm" (port I/O identyczne) — plan zmienia tylko rejestry adresu
  bufora i ABI wrapperów. §4 (BlockDevice `unsigned`/`off_t`) świadomie odłożone do Planu 7
  (pełny sweep LP64) — tu trzymamy się minimalnych/addytywnych zmian.
- **Granica MI/MD:** całe MD storage w `arch/x86_64/drivers/`; `Kernel.cpp` (MI) niezmieniony,
  woła wyłącznie `<arch/block.h> arch::bootDisk()`. `check-arch` to pilnuje (Task 6).
- **Kolizje nazw obiektów:** elf32 i686 vs elf64 x86_64 we współdzielonym `bin/` — rozwiązane
  sufiksem `64` (`ATA64.o`, `Hdd64.o`, `AtaBlockDevice64.o`) i odrębną bazą (`block_x86_64.o`);
  wszystkie wylistowane w `arch/x86_64/arch.mk`. Zgodne z precedensem `loader64.o` z Planu 1.
- **Poprawność ATA64.S:** port I/O bez zmian; `rep insw`→`[RDI]`, `rep outsw`→`[RSI]` (64-bit
  address size w long mode) — bufor ładowany z `RDX` (3. arg SysV) do `RDI`/`RSI`; timeout
  trzymany w wolnym rejestrze (`ESI` w read, `EDI` w write — przeciwnym do bufora); LBA 28-bit
  pozostaje w `EAX`/`EBX`; `pushfq`/`popfq` + 64-bit push/pop; FLUSH CACHE (0xE7) zachowany.
- **Jedna komenda na sektor:** zachowana w `AtaBlockDevice64::read/writeSectors` (kwirk i686
  `rep insw` jest identyczny w long mode).
- **Placeholdery:** brak — każdy krok ma realny kod/komendę i oczekiwany wynik; boot,
  self-test i `e2fsck` są wykonywalne bez dodatkowego kontekstu.
- **Założenia z Planów 2–4** jawnie wypisane w „Zależności"; Task 3 uzgadnia ewentualny inny
