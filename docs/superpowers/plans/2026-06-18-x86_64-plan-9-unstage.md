# x86_64 Plan 9 — Un-stage: scheduler/fork/csprng/PCI/input + boot the real Kernel.cpp

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the **staged** x86_64 kernel (`arch/x86_64/boot/KernelStage64.cpp`, linked from `STAGE64_OBJS`) with the **real machine-independent `kernel/Kernel.cpp`** linked via `make ARCH=x86_64 _all` into `bin/kernel.bin`. To do that, port the last i686-only machine-dependent subsystems to `arch/x86_64/` — the scheduler context switch, `fork`/`clone`, the CSPRNG entropy source, PCI config access, and the keyboard input/line-discipline — and widen the `arch/sched.h` contract to 64-bit. After this plan the full x86_64 kernel boots from the disk image, runs the scheduler, reaches its normal init path, and `init.nxe` runs as PID 1 in ring 3 (unblocking Plan 8's app ports, which need the full POSIX syscall surface + fork/exec + dynamic linking + networking).

**Architecture:** Migration-replacement (spec `docs/superpowers/specs/2026-06-15-x86_64-migration-analysis.md`). Plans 1-7 proved every hard mechanism and left the kernel STAGED because the full `Kernel.cpp` pulls `Scheduler`/`Process`/`Signal`/`Futex`/the net stack/`Csprng`/`DynLoader`/`KextLoader`/the framebuffer console — all MI (and LP64-swept in Plan 7) but resting on MD contracts (`<arch/sched.h>`, `<arch/random.h>`, `<arch/pci.h>`, `<arch/input.h>`) that have **no x86_64 implementation yet**. This plan fills `arch/x86_64/cpu/` + `arch/x86_64/io/` with those impls (mirroring `arch/x86/`), widens `<arch/sched.h>` to LP64, then flips the x86_64 build from the staged link to the real `_all` link and boots `kernel/Kernel.cpp` unchanged. i686 stays green throughout (separate `arch/x86/arch.mk`; conditional typing in shared contracts).

**Tech Stack:** `x86_64-elf-` cross-toolchain (Plan 1), NASM `-f elf64`, GNU ld, `qemu-system-x86_64 -drive`, Docker `nanos-build`, host `g++`+doctest for the MI scheduler/csprng/pci host tests. Patterns: System V AMD64 callee-saved set for the context switch (`rbx, rbp, r12-r15`), `RDRAND`/`RDTSC`, PCI mechanism #1 (ports 0xCF8/0xCFC), PS/2 keyboard line discipline.

### Reference (i686 templates — the executing agent reads these as the logic spec)
- Scheduler MD: `arch/x86/cpu/sched_x86.cpp`, `arch/x86/cpu/switch.S`, `arch/x86/cpu/fork_x86.cpp`
- CSPRNG MD: `arch/x86/cpu/random_x86.cpp`
- PCI MD: `arch/x86/io/pci_x86.cpp` (or wherever `pciConfigRead32` lives — grep)
- Input MD: `arch/x86/drivers/input_x86.cpp`
- Contracts: `arch/include/arch/{sched,random,pci,input}.h`
- MI consumers (must keep compiling/linking, LP64): `kernel/Scheduler.*`, `kernel/Process.*`, `kernel/Signal.*`, `kernel/Futex.*`, `kernel/Csprng.*`, `kernel/Pci.*`, `net/*`, `kernel/DynLoader.*`, `kernel/Kernel.cpp`.

### Decisions baked into this plan
- **#A — `<arch/sched.h>` goes 64-bit.** Kernel stack pointers and CR3 are 64-bit on x86_64. Widen the contract: `archContextSwitch(uintptr_t* saveOldKesp, uintptr_t newKesp)`, `archTaskBootstrap(unsigned char*, uint64_t cr3) -> uintptr_t`, `archKernelCr3() -> uint64_t`, `setKernelStack(uintptr_t)`, `archForkChild/archCloneChild` cr3/userEsp → `uint64_t`/`uintptr_t`. On i686 `uintptr_t == unsigned (32-bit)` so the i686 impl + the MI Scheduler/Process callers are unchanged in behaviour; this is the same "widen the contract, both arches green" move Plan 7 used. The MI `Scheduler`/`Process` store these in `uintptr_t` fields (Plan 7 may already have done part of this — reconcile).
- **#B — reconcile the two "kernel stack" notions.** Plan 6 introduced a per-CPU `g_percpu.kernelStackTop` (read by the SYSCALL stub after `swapgs` at `[gs:0]`) AND the TSS `rsp0` (used by `iretq`/interrupt CPL change). The scheduler's `setKernelStack(rsp0)` must update BOTH on every switch (TSS.rsp0 for interrupt/iretq entry, and the per-CPU slot for the syscall stub) so a trap/syscall from a ring-3 task lands on THAT task's kernel stack. The real `cpu_x86_64.cpp`/`Gdt64` own the TSS; wire `setKernelStack` to set `tss.rsp0` + `g_percpu.kernelStackTop`.
- **#C — `init.nxe` path.** The real `kernel/Kernel.cpp` execs PID 1 from its normal path (`/disks/main/nanos/core/init.nxe` or the `/bin/init.nxe` symlink — match what `Kernel.cpp` actually does). The disk image's `_image64` already installs the 64-bit `init.nxe`; ensure the path the real `Kernel.cpp` uses is the one populated. The full `Syscalls` core (not the staged minimal dispatch) now handles syscalls.
- **#D — single CPU.** No SMP. The scheduler is the existing round-robin single-core one; this plan only provides its MD context switch, not multiprocessor support.

## Task 2: x86_64 context switch — `switch64.S` + `sched_x86_64.cpp`

**Files:** Create `arch/x86_64/cpu/switch64.S`, `arch/x86_64/cpu/sched_x86_64.cpp`. Read `arch/x86/cpu/switch.S` + `sched_x86.cpp` as the template.

- [ ] **Step 1: `switch64.S` — `archContextSwitch(uintptr_t* saveOldKesp, uintptr_t newKesp)`.** SysV AMD64: arg0=`rdi` (saveOldKesp), arg1=`rsi` (newKesp). Push the callee-saved set `rbx, rbp, r12, r13, r14, r15` (NOT r10/r11/etc — only callee-saved survive a call), save CR3 if the switch changes address spaces (mirror i686 — i686 pushes CR3 too), `mov [rdi], rsp` (save old kernel rsp), `mov rsp, rsi` (load new), pop the callee-saved set + restore CR3, `ret`. Provide `ret_from_fork` (the label fork's fabricated stack returns into — restores the trap frame and `iretq`s to ring 3). Match the i686 `switch.S` structure exactly, translated to 64-bit registers + the SysV callee-saved set.

- [ ] **Step 2: `sched_x86_64.cpp`** — implement the rest of `<arch/sched.h>`:
  - `archTaskBootstrap(unsigned char* kstackTop, uint64_t cr3) -> uintptr_t`: fabricate a fresh kernel stack so the first `archContextSwitch` into it `ret`s into the task trampoline (mirror i686: push the trampoline address + zeroed callee-saved + cr3 in the same order `archContextSwitch` pops). Return the fabricated rsp.
  - `archKernelCr3() -> uint64_t`: return `arch::mmuKernelDirPhys()` (Plan 3).
  - `setKernelStack(uintptr_t rsp0)`: set TSS `rsp0` (the Gdt64/cpu TSS from Plan 4) AND the per-CPU `g_percpu.kernelStackTop` (Plan 6 syscall stub) — decision #B. Expose whatever setter `cpu_x86_64.cpp`/`Gdt64` provide; add one if needed.
