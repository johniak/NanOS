# i686/32-bit Flow Retirement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the retired i686/32-bit build flow from NanOS + nanos-sdk so x86_64 is the only architecture, with the full verify64 gate and representative port rebuilds green after the cut.

**Architecture:** Pure deletion/collapse refactor. The x86_64 flow already has its own mirrors of everything (arch/x86_64, _userland64/_image64, mknx64, user-nx.ld, kext64.ld, Limine image); the work is deleting the 32-bit half and collapsing every `ifeq ($(ARCH),x86_64)/else` fork into its x86_64 branch. Behavioural change to the 64-bit flow must be zero, except: `ARCH` defaults to `x86_64` (so `make zlib` == `make ARCH=x86_64 zlib`) and host tests compile `arch/x86_64/boot/MultibootMmap.cpp` instead of the byte-identical i686 copy.

**Tech Stack:** GNU make, Docker (nanos-build container), bash scripts, doctest host suite.

## Global Constraints

- Commits/PRs must omit ALL Claude/AI co-author and "Generated with" trailers.
- Work directly on `develop` (repo convention; no worktree).
- Zero behavioural change to the x86_64 flow other than the ARCH default and the MultibootMmap test-module path (files verified identical).
- `nanos-sdk/toolchain/patch.sh` is NOT touched: it is upstream-patch machinery whose i686 hunks share files with the x86_64 hunks; removing them risks the (unverified-from-source) toolchain build for zero runtime benefit. i686-nanos is instead documented as retired.
- `bringup64` + the grub-pc i386-pc module fetch in docker/Dockerfile STAY (grub-mkrescue for the x86_64 rescue ISO uses the i386-pc BIOS modules — that's a GRUB implementation detail, not the i686 NanOS flow).
- NetSurf: repo + bootstrap clone stay; `make netsurf` becomes an explicit error stub naming the browser-on-x86_64 follow-up.
- Final gate: `make verify64` green + `make externals` (14/14) + `make image64 image64-gl` + `make zlib ping grep` with NO `ARCH=` argument + boot smokes.

## Survey results the tasks rely on

- `arch/x86/` = 45 tracked files; the only cross-references from live x86_64 code/tests are:
  - `tests/test_gdt.cpp` includes `../arch/x86/cpu/GdtBase.h` (used by nothing else; 32-bit GDT packing test → delete both, drop `"*/GdtBase.*"` from COV_PATTERNS).
  - Host tests compile `arch/x86/boot/MultibootMmap.cpp` (TEST_MODULES) with `-Iarch/x86/boot` (HINCLUDES). `arch/x86_64/boot/MultibootMmap.cpp` is byte-identical (verified with diff); the .h differs (LP64 mirror) → switch both references to arch/x86_64 and let test64 arbitrate.
- 32-bit-only Makefile chains: `build`/`image`/`iso`/`run`/`run-iso`/`run-net` (host side) → `_all(ARCH=x86)`/`_image`/`_iso`/`_disk-image` (container side) → `_userland` (`USER_PROGS`/`SYS_PROGS`/`APP_PROGS`) + legacy GRUB branch of `scripts/create-image.sh`. x86_64 uses `_image64`/`_userland64`/`X64_USER_PROGS` throughout.
- `rustform` is the only i686-only userland program (cargo target `user/rust/i686-nanos.json`, links `user/nx.ld` with 32-bit `$(MKNX)`); x86_64 has `rsexp` + `libnwui-rs`.
- Dual-arch variables to collapse: `BASH_ENV/BASH_PREREQ`, `PING_*`-family per-port TRIPLE/ENV blocks (openssl, dropbear, zlib, ncurses, libpng, libjpeg, wget, git, inetd, httpd, udhcpc…), `PICOLIBC`, `USER_ARCHFLAGS`, `MKNX_TOOL`, `USER_NX_LD`, `ARCH_MM_INC`/`ARCH_ADDRSPACE`/`ARCH_PAGING_TESTS_EXCL`, `QEMU_CPU ?= -cpu Nehalem` host-side default.
- 32-bit files outside arch/x86: `user/nx.ld`, `kext/kext.ld`, 32-bit crt0/sigtramp startup sources (identify by grepping the `$(BINFOLDER)crt0.o` rule chain for the non-64 sources), `bin/mknx` build rule (32-bit tool), `user/rust/rustform/`, `user/rust/i686-nanos.json`, `docker/picolibc-i686-elf.txt`.
- docker/Dockerfile layers to remove: i686-elf binutils+gcc (the FIRST toolchain layer — removal invalidates the whole cache → one full ~1h container rebuild), i686-elf picolibc. Rust layer stays (rsexp), grub-pc fetch stays.
- nanos-sdk: `build-toolchain.sh` already defaults x86_64-nanos ("i686-nanos retired"); to fix: `scripts/bootstrap.sh` step label `toolchain (x86_64-nanos + i686-nanos)`, the echo'd recipe (`make ARCH=x86_64 …` prefixes + `&& make netsurf`), `toolchain/gen-conftest-stubs.sh` i686 defaults, `picolibc-i686-elf.txt`, README notes. `ports.manifest` has zero i686 refs.
- Local workspace cleanup (not repos): `~/Projects/nanos-sdk-work/toolchain/i686-nanos` (99 MB).
