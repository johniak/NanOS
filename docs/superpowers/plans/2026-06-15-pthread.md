# Full pthread on NanOS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real `-lpthread` software runs unmodified on NanOS — a 1:1 kernel-thread model (each pthread is a `Task` sharing its process's address space + fds), Linux-ABI threading syscalls, GS-based TLS, and musl's NPTL pthread ported onto picolibc.

**Architecture:** Build on the existing preemptive `Task` scheduler. Add `clone`/`futex`/`set_thread_area`/`set_tid_address`/`gettid`/`tgkill`/`exit_group` with Linux i386 semantics. Make the libc thread-safe (per-thread errno in the TCB, picolibc locks → futex). Port musl pthread for correct primitives + cancellation.

**Tech Stack:** C++ kernel (`int 0x80` syscalls, MI/MD split), i686 GS TLS via GDT, picolibc + `user/libc-glue` (musl pthread grafted), doctest host tests, QEMU for runtime.

Spec: `docs/superpowers/specs/2026-06-15-pthread-design.md`. Constraint: **uniprocessor — concurrency, not parallelism.** Branch: work on `feat/nap-package-manager` (current) or a fresh branch; commit after each task. Commits/PRs contain **no** mention of AI.

## Phase 1 — futex

Goal: the `futex(2)` syscall, the primitive every pthread sync object is built on. Keep the matching logic pure + host-tested; wire it to `Scheduler` block/wake.

### Task 1.1: Pure futex wait-bucket logic (host-tested)

**Files:**
- Create: `kernel/Futex.h`, `kernel/Futex.cpp`
- Test: `tests/test_futex.cpp` (add to `TEST_MODULES` + `COV_PATTERNS`)

> **Key design (important — a bare VA is not a unique key).** Two different address spaces can both have a futex at VA `0x1000`; keying buckets by the raw `uaddr` alone would let one process's `FUTEX_WAKE` spuriously wake another's waiter. A futex key is therefore the pair **`(AddressSpace*, uaddr)`** — `FutexKey{ const void* space; void* uaddr; }`, equal iff both match. For pthreads this is exactly right: every thread of a process shares one `AddressSpace`, so a `FUTEX_PRIVATE` futex is scoped to its process. **Process-shared futexes (`FUTEX_PRIVATE` clear, a futex in `MAP_SHARED` memory across processes) are out of scope** — they would need keying by physical frame; the syscall returns `-ENOSYS` for the shared case (logged once) rather than silently mis-scoping. `FutexTable` takes the `space` from the caller (the kernel passes `ProcTable::current()->space`); host tests pass distinct dummy pointers.

- [ ] **Step 1: Failing test** — bucket keyed by `(space, addr)`; same addr in two spaces is independent; wake returns the count actually woken; requeue moves waiters.

    CHECK(ft.count(sp1, A) == 1);

## Phase 2 — clone + TLS + tid

Goal: create a real second thread in a process. Milestone: a hand-written assembly/`clone`-using program spawns a thread that writes to shared memory and exits, joined via the CLEARTID futex.

### Task 2.1: A single per-CPU TLS GDT descriptor, reloaded on every switch

> **Why one descriptor, not a pool.** The GDT is tiny — `GdtEntry gdtEntries[6]` (null, ring0 code/data, ring3 code/data, TSS) in `arch/x86/cpu/Gdt.h:25`. A "pool of 8" TLS slots both doesn't fit and caps the thread count (the stress test wants dozens). On a uniprocessor only **one** thread runs at a time, so one dedicated TLS descriptor suffices: grow the table to **7** entries, reserve index 6 as *the* TLS slot, and on every context switch re-point its base at the now-current thread's `tlsBase` and reload `GS`. This scales to any number of threads with zero per-thread GDT bookkeeping. `set_thread_area` then just records `tlsBase` on the `Thread` (and, if it's the current thread, loads it immediately).

**Files:**
- Modify: `arch/x86/cpu/Gdt.{h,cpp}` (grow `gdtEntries` to 7; add the TLS entry + `gdtSetTlsBase(base)` that rewrites entry 6's base and reloads `GS=0x33` (`(6<<3)|3`)), `arch/include/arch/cpu.h` (contract: `archSetThreadArea(base)`, `archLoadThreadTls(base)`), `arch/x86/cpu/cpu_x86.cpp`
- Test: pure base-encoding host test in `tests/test_gdt.cpp` (the descriptor base/limit packing).

## Phase 3 — thread-safe libc

Goal: make picolibc + libc-glue safe under threads BEFORE pthread, or the first real program corrupts state. Per-thread errno via the TCB; picolibc retarget-locks → futex; malloc/stdio locks.

### Task 3.1: Per-thread errno in the TCB

> **The current model imports `errno` as a DATA slot — that has to change.** Today `user/libc-glue/nx-dllimport.h:42,48` does `extern int *__imp_errno;` + `#define errno (*__imp_errno)` — the loader binds one libc.ndl data object as the single, process-wide errno. A per-thread errno cannot be a single data address. Switch the program-side ABI to the **function** form every threaded libc uses: import `__errno_location` (a function, which the `.ndl` loader resolves like any code export) and define `#define errno (*__errno_location())`. libc.ndl's `__errno_location` returns `&__pthread_self()->__errno`, so each thread gets its own. Drop the `__imp_errno` data slot entirely (no more single source of truth); every program is rebuilt against the new header (they all are, from source). Picolibc internally references `errno` through the same macro, so its functions and app code share the one per-thread cell.

**Files:**
- Modify: `user/libc-glue/nx-dllimport.h` (errno → `(*__errno_location())`; remove `__imp_errno`), a new `user/libc-glue/tcb.h` (the `struct __pthread` TCB layout: `self`, `tid`, `__errno`, cancel fields), `user/libc-glue/errno_location.c` (the `__errno_location` export), the `crt0`/thread-pointer setup, `Makefile` (drop `__imp_errno` from the libc.ndl export list / dllimport.S)
- Test: QEMU (two threads see independent errno after Phase 4) — for now an existing single-thread program that reads errno still works.

The thread pointer (GS:0) points at the TCB; `__pthread_self()` reads GS:0. Implement `int *__errno_location(void){ return &__pthread_self()->__errno; }` and **export it from libc.ndl**. In `nx-dllimport.h`, replace the `__imp_errno` block with `extern int *__errno_location(void);` + `#define errno (*__errno_location())`. ### Task 4.1: Vendor + adapt the musl internals (`__clone`, `__syscall`, `__lock`, `__timedwait`)

**Files:**
- Create: `user/libc-glue/pthread/` (musl `src/thread/__lock.c`, `__timedwait.c`, `__wait.c`, `__set_thread_area` for i386, `clone.s` i386, `pthread_self.c`), `user/libc-glue/include/pthread.h`, `bits/` headers
- Modify: `Makefile` (compile the pthread sources into libc.ndl; add `-I` for the musl headers)

> **Two distinct `clone`s — don't conflate them.** The **raw kernel syscall** is `clone(flags, child_stack, ptid, tls, ctid)` (i386: `ebx=flags, ecx=child_stack, edx=ptid, esi=tls, edi=ctid`; returns the new tid to the parent, 0 in the child *on the new stack*). musl's **C wrapper** is `int __clone(int (*fn)(void*), void *stack, int flags, void *arg, pid_t *ptid, void *tls, pid_t *ctid)` — `fn`/`arg` are *wrapper* concerns: its `clone.s` issues the raw syscall, and on the child path (where the kernel returns 0) it pops `fn`/`arg` off the new stack and calls `fn(arg)`, then `exit`s with the result. So `pthread_create` calls **`__clone`** (with `fn`/`arg`); only `__clone`'s asm speaks the raw 5-arg syscall ABI. Keep them straight.

- [ ] **Step 1:** Bring musl's i386 `__clone` (`src/thread/i386/clone.s`) verbatim where possible — it issues the raw `clone` syscall and, on the child, calls the start fn off the new stack. Adapt only the syscall number/convention to NanOS (`int 0x80`, `clone == 120`, args `ebx/ecx/edx/esi/edi`). `__set_thread_area.c` (i386) → `set_thread_area(243)`. `__timedwait`/`__wait` → `futex(240)`. `pthread_self` → `__pthread_self()` (GS:0). `__lock`/`__unlock` → the futex mutex.

## Phase 5 — signals + cancellation

### Task 5.1: Widen the kernel signal representation to make room for `SIGCANCEL`

> **Why this comes first.** `pthread_cancel` rides a reserved real-time signal, but the kernel today tops out at `NANOS_NSIG == 32` with **32-bit** masks (`SignalState`/`ThreadSignals.blocked,pending` are `unsigned`), valid signals **1..31** (`kernel/Signal.h:70`). Linux/musl put `SIGCANCEL` at `__SIGRTMIN` = **32**, which doesn't exist here, and there is no free in-range slot that matches the musl ABI. Widen the representation to **64 signals** (`uint64_t` masks, `NANOS_NSIG = 65`) so real-time signals `32..64` exist — this is also what real apps that use `SIGRTMIN`/`SIGRTMAX` need — and reserve `SIGCANCEL = 32`.

**Files:**
- Modify: `kernel/Signal.h` (mask fields `unsigned` → `uint64_t`; `NANOS_NSIG` 32 → 65; `#define SIGCANCEL 32`; mask helpers `1u<<` → `1ull<<` with `(sig-1)` bit), the `ThreadSignals`/`ProcSignals` types from Task 0.3, `kernel/SignalDispatch.*` (any `unsigned mask` locals), `kernel/Syscall.cpp` (sigprocmask/sigpending pass 64-bit `sigset_t`)
- Test: `tests/test_signal.cpp` (extend) — a signal above 31 sets/clears in the wide mask.
