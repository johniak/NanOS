# Full pthread on NanOS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real `-lpthread` software runs unmodified on NanOS — a 1:1 kernel-thread model (each pthread is a `Task` sharing its process's address space + fds), Linux-ABI threading syscalls, GS-based TLS, and musl's NPTL pthread ported onto picolibc.

**Architecture:** Build on the existing preemptive `Task` scheduler. Add `clone`/`futex`/`set_thread_area`/`set_tid_address`/`gettid`/`tgkill`/`exit_group` with Linux i386 semantics. Make the libc thread-safe (per-thread errno in the TCB, picolibc locks → futex). Port musl pthread for correct primitives + cancellation.

**Tech Stack:** C++ kernel (`int 0x80` syscalls, MI/MD split), i686 GS TLS via GDT, picolibc + `user/libc-glue` (musl pthread grafted), doctest host tests, QEMU for runtime.

Spec: `docs/superpowers/specs/2026-06-15-pthread-design.md`. Constraint: **uniprocessor — concurrency, not parallelism.** Branch: work on `feat/nap-package-manager` (current) or a fresh branch; commit after each task. Commits/PRs contain **no** mention of AI.

```cpp
struct Task;     // Scheduler.h
struct Process;

// One thread of execution within a process (thread group). The Task is the scheduler
// context; the rest is per-thread state that used to live (implicitly) on the Process.
struct Thread {
    bool     used;
    int      tid;            // system-wide unique; leader thread tid == process pid
    Task*    task;           // scheduler context for this thread
    Process* proc;           // owning thread group
    unsigned userStackTop;   // base of this thread's user stack (for teardown); 0 = leader/main
    unsigned tlsBase;        // TLS block VA (set_thread_area); 0 until set
    int      tlsGdtSlot;     // GDT entry index backing GS for this thread; -1 = none
    unsigned clearTidAddr;   // set_tid_address: zero+futex-wake here on exit; 0 = none
    SignalState sig;         // per-thread signal mask + pending (dispositions stay on Process)
    bool     exiting;        // this thread is tearing down
    Thread*  next;           // intrusive list within the process
};
```

Add to `struct Process`: `int tgid;`, `int threadCount;`, `Thread* threads;` (head of the list). Move `SignalState sig;` semantics: keep the process-wide **dispositions** on `Process` (rename clearly, e.g. keep `sig` for dispositions+process-pending), and put the per-thread **mask+pending** on `Thread::sig`. (If `SignalState` mixes both, split it — see Task 0.2.)

In `kernel/Process.cpp::create`, allocate the leader `Thread` (tid = pid, task = the process's task, all other per-thread fields zero/`-1`), set `tgid = pid`, `threadCount = 1`, link it as the only thread. Add `Process::leaderThread()` (or `ProcTable::leaderThread`) returning the head thread, and `Thread* ProcTable::threadByTid(int tid)`.

## Phase 1 — futex

Goal: the `futex(2)` syscall, the primitive every pthread sync object is built on. Keep the matching logic pure + host-tested; wire it to `Scheduler` block/wake.

### Task 1.1: Pure futex wait-bucket logic (host-tested)

**Files:**
- Create: `kernel/Futex.h`, `kernel/Futex.cpp`
- Test: `tests/test_futex.cpp` (add to `TEST_MODULES` + `COV_PATTERNS`)

- [ ] **Step 1: Failing test** — bucket keyed by address; wake returns the count actually woken; requeue moves waiters.

```cpp
TEST_CASE("futex buckets: wait enqueues, wake removes up to N, requeue moves waiters") {
    kernel::FutexTable ft;
    void* A = (void*)0x1000; void* B = (void*)0x2000;
    kernel::FutexWaiter w1{}, w2{}, w3{};
    ft.enqueue(A, &w1); ft.enqueue(A, &w2); ft.enqueue(A, &w3);
    CHECK(ft.wake(A, 2) == 2);              // wakes 2 of 3 (FIFO)
    CHECK(ft.count(A) == 1);
    ft.enqueue(B, &w1);                      // (reuse after dequeue)
    CHECK(ft.requeue(A, B, /*wake*/0, /*move*/100) == 1); // move the remaining A-waiter to B
    CHECK(ft.count(A) == 0);
    CHECK(ft.count(B) == 2);
}
```

- [ ] **Step 2: Run it, watch it fail.**

- [ ] **Step 3: Implement `FutexTable`.** Hash `void*` → bucket; each bucket an intrusive FIFO of `FutexWaiter{ void* uaddr; Task* task; uint32 bitset; FutexWaiter* next; }`. Methods: `enqueue(uaddr,w)`, `wake(uaddr,n)` (dequeue+return ≤n), `wakeBitset(uaddr,n,bitset)`, `requeue(from,to,nwake,nmove)`, `count(uaddr)` (test helper), `remove(w)` (timeout/signal cancel). No allocation — `FutexWaiter` lives on the waiter's kernel stack.

- [ ] **Step 4: Run it, watch it pass.** `make test` → PASS. **Step 5:** `make check-arch` clean. **Step 6: Commit** `kernel: futex wait-bucket table (pure, host-tested)`.

## Phase 6 — lifecycle + real-app gate

### Task 6.1: `fork`/`exec` in a multithreaded process

**Files:** `kernel/Syscall.cpp` (`fork`, `execve`); test `user/pthrtest.c` extension + QEMU.

- [ ] **Step 1: Test** — a process with 3 live threads calls `fork`; the child has exactly 1 thread (the caller) and runs correctly; then `execve` in the child replaces the group. **Step 2: Implement** — `fork` copies only the calling thread into the new (copied) address space; reset `threadCount=1`. `execve` terminates all sibling threads, frees their stacks/TLS, collapses to one thread, then loads the new image. **Step 3:** QEMU → `fork-in-mt ok`. **Step 4: Commit** `kernel: fork/exec semantics in a multithreaded process`.
