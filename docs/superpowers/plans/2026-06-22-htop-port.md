# htop Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run unmodified upstream htop 3.x as a NanOS `.nxe` (x86_64) using htop's Linux `/proc` backend, showing live CPU/memory/load meters and a real process list.

**Architecture:** Two halves. (1) A `nanos-sdk` port — htop is an ncurses-linking autotools app, cross-built to `x86_64-nanos` by the `nanos-port` driver from a new `~/Projects/nanos-sdk-work/htop-port/`, wired into NanOS via a `make htop` target and an `_image64` install block, mirroring the existing `make vim` port. (2) NanOS `/proc` extensions in `fs/SynthFs.cpp` + `kernel/Process.{h,cpp}` so htop's Linux backend finds the per-process and system fields it reads (statm, real vsz/rss, status Uid/VmRSS/Threads, extra meminfo keys).

**Tech Stack:** C++ (freestanding kernel), C (htop upstream), autotools, the `nanos-port` Python driver, ncurses (`libncurses.a`/`libtinfo.a`, already in the x86_64-nanos sysroot), doctest (host tests), QEMU x86_64.

## Global Constraints

- **Target arch:** x86_64 only (`x86_64-nanos`). The htop port manifest is x86_64-only; the `make htop` i686 branch is not implemented.
- **Commit messages / PRs:** NO mention of Claude/AI — no `Co-Authored-By`, no "Generated with" trailer. Clean messages only.
- **Do not commit `CLAUDE.md`.**
- **TDD for all NanOS kernel/fs changes:** failing test → watch it fail → minimal code → pass → commit. Host tests run via `make test` (doctest, >90% line-coverage gate; new `fs/SynthFs.cpp` / `kernel/Process.cpp` lines are inside the gated `COV_PATTERNS`).
- **The macOS case-insensitivity trap:** never add `-Ilib` to a host-test include list; `<string.h>` must resolve to libc for tests and to `include/string.h` for the kernel. Don't touch `KINCLUDES`/`HINCLUDES`.
- **Honesty:** `/proc` fields must reflect real kernel state (or an explicitly-commented proxy). No fabricated constants presented as real metrics.
- **ncurses build inputs:** htop links `-lncurses -ltinfo` (NON-widechar; NanOS has `libncurses.a`/`libtinfo.a`, not `libncursesw.a`) → configure with `--disable-unicode`. Requires `make ARCH=x86_64 ncurses` to have populated the sysroot.
- **htop version:** the latest htop 3.x release tarball (e.g. `htop-3.3.0.tar.xz`). Record the exact version in `nxport.toml`'s comment.
- **`make image*` never depends on `make htop`** — a missing `bin/htop.nxe` is silently skipped by `_image64`.

### Task 3: `/proc/<pid>/statm` — new per-pid memory file

htop's `LinuxProcessTable_readStatmFile` reads `/proc/<pid>/statm` (whitespace-separated: `size resident shared text lib data dt`, in pages). NanOS does not serve `statm` at all (`PROC_FILES` lists only `comm`/`cmdline`/`stat`/`status`). Add it. NanOS has no page/text/shared split, so report `size == resident == memKb/4` (4 KiB pages) and the rest 0 — honest given the brk-only proxy.

**Files:**
- Modify: `fs/SynthFs.cpp` (`PROC_FILES` ~line 527; `renderProcFile` ~lines 542–594)
- Test: `tests/test_synthfs.cpp`

- Produces: `/proc/<pid>/statm` served by the existing read path (`SynthFs::read` already routes class-3 paths through `renderProcFile`; the existing `char tmp[320]` buffer in `read` is large enough for statm).

int statmString(char* buf, int cap, unsigned memKb) {
    unsigned pages = memKb / 4u;                 // 4 KiB pages
    int p = 0;
    p = putUint(buf, p, cap, pages);             // size
    p = putStr(buf, p, cap, " ");
    p = putUint(buf, p, cap, pages);             // resident (no swap: all resident)

}

- [ ] **Step 3: Write `hooks/pre_configure.sh`** (patch the platform selection + regenerate):

```sh
#!/bin/sh
# pre_configure.sh — teach htop's build that *nanos* uses the Linux /proc backend, then regenerate
# configure so the HTOP_LINUX automake conditional (which compiles linux/*.c) is active.
#
# htop's configure.ac selects $my_htop_platform from $host_os; an unknown OS falls to the
# "unsupported" stub platform. NanOS genuinely exposes a Linux-style /proc, so we map nanos -> linux.
set -e

# Add nanos to the linux arm of the platform case (robust to surrounding text). htop 3.x uses a
# `case "$host_os" in ... linux*|gnu*) my_htop_platform=...` block; widen that pattern.
if grep -qE 'linux\*\|gnu\*\)' configure.ac; then
  sed -i 's/linux\*|gnu\*)/linux*|gnu*|nanos*)/' configure.ac
elif grep -qE '\blinux\*\)' configure.ac; then
  sed -i 's/\blinux\*)/linux*|nanos*)/' configure.ac
else
  echo "  [pre_configure] ERROR: could not find the linux platform arm in configure.ac" >&2
  exit 1
fi
echo "  [pre_configure] mapped *nanos* -> htop linux platform in configure.ac"

# Regenerate configure/Makefile.in from the patched configure.ac (autotools are in the container).
autoreconf -fi
echo "  [pre_configure] autoreconf done"
```
