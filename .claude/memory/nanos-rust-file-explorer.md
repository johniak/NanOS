XP-style **file explorer written in Rust** (`rsexp`), the x86_64 nwm desktop's Files app
(replaces the C `nwexp`). Branch `feat/rust-explorer` (off `main`, 2026-06-27).

- Spec `docs/superpowers/specs/2026-06-27-rust-icon-explorer-design.md`; plan
  `docs/superpowers/plans/2026-06-27-rust-icon-explorer.md`. Supersedes a stale
  `feat/rust-icon-explorer` branch (was cut before the Dell fixes).
- **My Computer** = userland-synthetic: enumerate `/disks/*` (one drive each) + Home
  (`$HOME` = `/disks/main/users/jan`). No kernel change.
- **Reusable → libnwui** (the user's standing rule): `nwui_png.{c,h}` (PNG decoder promoted
  from nwm + `nwui_image_load_png`), `NWUI_ICONVIEW` icon grid + `NWUI_PANEL` titled
  glass group-box (the XP task pane), `nwui_fs.{c,h}` (opendir/readdir shim for non-C apps).
- **Icons:** real 48×48 PNGs under `/nanos/share/icons/`, generated by `tools/gen-icons.py`
  (stdlib only). Transparency = **magenta color-key** (`NWUI_ICON_KEY 0x00ff00ff`) because the
  decoder drops alpha; the iconview skips key pixels.
- **Rust x64:** new target `user/rust/x86_64-nanos.json` (SSE ON to match the C userland ABI —
  NOT soft-float like the kernel/i686). Reusable bindings crate `user/rust/libnwui-rs` (rlib:
  runtime + safe wrappers + raw-callback constructors). App `user/rust/rsexp` (staticlib). Built
  via `cargo build -Z build-std` like the i686 `rustform`; cargo target/ dirs gitignored
  (`user/rust/*/target/`).
- nwm Start menu gained "My Computer" → spawns `rsexp`; nwm autostart Files = rsexp.
- **SQLite-backed recursive search** (feature `sqlite`, links `libsqlite.ndl`) + per-directory
  sort persisted in `~/.rsexp.db` (right-click sort menu). See [[nanos-sqlite-port]] if present.
- **File management** (2026-06-28, `feat/rust-explorer`, commits da7ef98 + 21f80b9): New Folder,
  Rename, Delete (recursive, confirm dialog), Copy/Cut/Paste (recursive trees, collision-safe
  "name copy", self-paste guard), Refresh — via per-item right-click menu + Edit/File menus +
  accelerators (F2/Del/F5/Ctrl+N/C/X/V). Bottom **status bar** = item count / selected size /
  real **free space**. Built on new **`nwui_fs` flat-ABI shims** (mkdir/rename/remove/copy/size/
  exists/isdir/space), `nwui_confirm()`, and **keyboard-complete modals** (Enter=OK/Yes, Esc=
  cancel, prompt select-all). Real `statfs()`/`fstatfs()` added to libc-glue (SYS_statfs existed,
  wrapper didn't). Verified: host doctest 90.2%, native nwui_fs shim test (19/19), live QEMU
  (boot fault-free, dir view runs statfs, Ctrl+N→prompt→Enter→mkdir attempt + permission dialog).
- **Drag-and-drop between windows** (2026-06-28, commit f061091): compositor-arbitrated (only nwm
  knows geometry/z-order/cursor — the Windows OLE-drag model). Wire: NW_REQ_DRAG_BEGIN +
  NW_EVT_DRAG_MOTION/LEAVE/DROP (payload + ctrl/shift mods). nwm hit-tests the window under the
  cursor, routes events, DROP carries the payload. Toolkit iconview = drag source (press+move >
  threshold → on_drag → nwui_begin_drag) + drop target (drop-cell highlight, on_drop with cell +
  payload + mods). rsexp: drag a file onto a folder cell = move (Ctrl = copy), empty area = into
  cwd. All host-tested (nwm routing + toolkit gesture/drop). Headless drag can't be driven, so
  verified by host tests + clean boot.
- **Open-with** (commit 6ddc734): NW_REQ_SPAWN now carries optional "cmd\0arg"; nwm passes arg as
  argv[1] (spawn_client). nw_spawn_arg/nwui_spawn_arg + binding. nwnote = main(argc,argv) loads
  argv[1]. rsexp: activating a text file (.txt/.c/.h/.md/.cfg/.rs/.sh/.conf) opens it in nwnote.
- **Editable address bar** (commit 61756d6): breadcrumb is now a textfield — type a path + Enter
  to navigate; **Ctrl+L** focuses+selects it (browser-style). Toolkit got textfield on_submit
  (Enter, vs on_change), nwui_textfield_set, nwui_textfield_select_all. VISUALLY VERIFIED live
  (Ctrl+L → /disks/main/nanos/bin → Enter navigated). **Also fixed a DnD regression**: nwm nw_key
  was consuming the Ctrl scancode (return) → broke ALL client Ctrl+<key> accelerators; now tracked
  for drag-copy AND still forwarded.
- **macOS-style Cmd shortcuts EVERYWHERE** (2026-06-28, commit 55828af): NanOS uses Cmd (the
  Super/⌘ key) for ALL keyboard shortcuts, never Ctrl. nwm forwards unclaimed Cmd+<key> to the
  focused window with mods bit1 (system Cmd+C/X/V/Q/Tab/M/R stay compositor-owned); nwui_accel's
  modifier is now Cmd (matched off the mod bit). Cmd+C/X/V on a grid = FILE copy/cut/paste via
  nwui_iconview_set_clipboard (COPY/PASTE events). Documented in docs/{en,pl}/windowing.md §5.1.
  IMPORTANT: don't reintroduce Ctrl accelerators; don't make nwm `return` on the Ctrl scancode
  (that broke client Ctrl shortcuts once — it must forward modifier keys).
- **Reusable open() + image viewer** (commit a809aaf): nwui_open_file(u, path) = NanOS
  LaunchServices (.nxe runs; other files open in the app from extension associations in
  /nanos/config/associations.conf, built-in defaults, nwui_assoc_lookup). nwview = tiny image
  viewer reusing nwui_image_load_png + nwui_image (the .png open target). open respects file perms
  (access R_OK) + runs apps as the session user (6bb6f15).
- **Unified `open` — UI + terminal** (commit 0b40e92, macOS-style): nwm now listens on an AF_UNIX
  **launch socket** `/tmp/.nwm-spawn`; a non-window process connects + sends "cmd\0arg" and nwm
  spawns the app (resolve_cmd + spawn_client) as a new window client. **`open(1)`** = a tiny CLI
  (user/open/open.c, /nanos/bin) that resolves the association + asks nwm over the socket — so
  `open foo.png` from the **desktop Terminal** launches the Image Viewer (verified live). The
  ext→app resolver is SHARED: `user/open/launch.h` (static-inline `nw_file_ext`+`nw_assoc_lookup`,
  reads associations.conf) is included by BOTH the CLI and libnwui's nwui_open_file → UI + terminal
  open identically. Socket path const in `user/open/nwspawn.h`. Constraint (by design): the
  terminal must run inside the nwm session (socket exists while nwm runs); a non-window process
  can't draw, only ask nwm to launch. STILL future: GUI sudo-escalation (run an opened app as root).
- **Authenticate-to-open / GUI sudo-escalation** (2026-06-28, commit e6e2e4a, macOS-authorization
  style): opening a file the user can't read pops a modal **password dialog** instead of "permission
  denied". KEY GOTCHA: NanOS `access()` optimistically assumes uid 0 (never returns EACCES), so
  `nwui_open_file` now probes readability with `open(O_RDONLY)` and triggers the dialog on
  EACCES/EPERM. New `nwui_textfield_set_secret` masks the field as dots; Enter submits (modal_default).
  The launch goes over the SAME launch socket with the password appended ("cmd\0arg\0password");
  `nw_launch_send(cmd,arg,password)` in launch.h is shared by UI + terminal open(1) (open sends an
  empty password = unprivileged). On a non-empty password nwm execs the new **setuid-root `nwsu`**
  (`user/open/nwsu.c`, mode 04755 via debugfs in _image64 next to chsh) which verifies the password
  against root (shadow→passwd, same as nwlogin), setuid(0)s, scrubs NW_AUTH_PASS, and execs the app
  as root. Password travels via env (NW_AUTH_PASS), not argv → not in the process list. Verified
  LIVE: jan opens a root-owned 0600 file → auth dialog → root password → file opens as root in
  Notepad ("TOP SECRET — readable only by root" shown). Host tests 774/774, 90.2%.
  **REDESIGNED (commit e9c4775)**: the auth prompt is now a COMPOSITOR-OWNED system dialog (macOS/
  Windows-style), NOT a libnwui modal in the app. nwm draws a dimmed full-screen overlay + centered
  panel (lock badge / "<app> wants to make changes" / masked field / Cancel+Authenticate), captures
  ALL kbd+mouse while open (even Super+R blocked) → blocks the whole session. nwm collects the
  password ITSELF (client never sees it); on submit the shell runs the target as root via setuid
  nwsu. Launch-socket 3rd field is now a MODE ("elevate"), not a password — a client hitting EACCES
  just requests elevate. Invokable from ANYWHERE: explorer (nwui_open_file) AND terminal (`open
  /disks/main/<root-only-file>`). Logic in host-tested nwm_core (nw_auth_begin/rect/btn_rect/hit/
  key/cancel/submit/take, +4 tests). Old app-drawn nwui_auth_dialog removed. Live-verified x64.
  Up-nav fix (commit 17ee4bf): rsexp Up climbs the real fs /disks/main->/disks->"/" and stops, never
  jumps to My Computer (that's Back's job); added Cmd+Up (⌘↑); fixed accel_fire to honour the Cmd
  modifier on fkey accels (plain Up != Cmd+Up). 784 host tests pass.
- **Settings real categories** (commit 9dd0e54): nwset sidebar switches panels — Appearance /
  Desktop (clock) / Default Apps (file associations editor). Built on reusable nwui_set_visible
  (show/hide a node+subtree; basis for tabs). Fixed "everything in Appearance".
- Reusability (the user's standing rule, reaffirmed): file ops (nwui_fs), dialogs, DnD, clipboard,

**Why color-key not alpha:** the toolkit PNG decoder returns 0x00RRGGBB (alpha ignored), so true
transparency needs the key trick. **Why SSE-on target:** x64 userland uses SSE/hardware-float
(Makefile line ~1760), unlike the `-mno-sse` kernel. See [[nanos-notepad-libnwui]] (libnwui
growth), [[nanos-rust-kernel-migration]] (the other Rust effort), [[no-shortcuts-on-foundations]].
