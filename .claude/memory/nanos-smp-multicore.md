SMP/multicore for NanOS x86_64, branch **feat/smp**, plan `docs/superpowers/plans/2026-06-23-smp-multicore.md`.

**Done & verified:** Phase 1 (spinlock, ACPI MADT, LAPIC IPI), Phase 2 (AP trampoline + INIT-SIPI-SIPI, 4 cores online), Phase 3 Tasks 7-9 (Big Kernel Lock; per-CPU scheduler + finish_task_switch handoff; per-CPU GDT/TSS + AP scheduler entry + per-CPU LAPIC timer). smoke-smp + smoke-x86_64 + test64 all green.

**Fixed this session (commit 0895c2b):** the box froze right after "SMP: N CPUs online" / interactive login hung. Root cause = AP swapgs GS-base parity. An AP left the trampoline with active GS.base=0; `perCpuInitThis` set only KERNEL_GS_BASE, so the AP ran ring 0 in *user* parity → first exit-to-ring3 swapgs inverted it → next syscall loaded GS.base=0 → `mov %gs:0,%rsp` read the IVT (phys 0) as the kernel stack → wedge + BKL deadlock. Fix: set BOTH GS bases to the per-CPU block in perCpuInitThis (idempotent swapgs; NanOS user TLS is %fs not %gs), AND reorder apEntry64 so the GS-base write follows `archApCpuInit` (the GDT load reloads %gs and zeroes its hidden base). BSP was immune (archEnterUser doesn't swapgs). After the fix 4-CPU login completes through the raw/no-echo password read.

**Fixed this session (commit c716e60) — Task 10 DONE.** The ~16s-idle triple fault + the pfract crash were ONE bug: a **wake-during-switch-out double-dispatch**. `schedule()` does `g_bkl.exit()` BEFORE `archContextSwitch` saves the outgoing task's kesp; a task that voluntarily BLOCKED can be woken→READY by another CPU in that window and claimed before its kesp is saved → two CPUs run it, the save races the load (caught: `*kesp` = a live RBP into the task's own stack, e.g. 0x180719e0, kesp 0x180719c0, multiple CPUs picking the same daemon as READY). The `runningCpu` finish_task_switch handoff protected PREEMPTED tasks but the claim never checked `runningCpu`. **Fix:** `pickReady`/`pickNextTask` now require `runningCpu == -1` (context fully saved + released by `finishSwitch`) in addition to TASK_READY + non-idle. New host test covers it. Debugged via safe detectors (page-align check on the to-be-loaded CR3 — real PML4 is page-aligned, the corrupt value wasn't — kstack-overlap check, reap-running check); all removed after the fix (no band-aids).

**Task 10 speedup PROVEN (2.78x on 4 cores):** rewrote `user/pfract` to STATIC work partitioning + per-worker local accumulator — parallel section is pure ring-3 compute, ZERO syscalls, ZERO shared writes (old shared mutex+condvar queue funneled every row pull through futex() under the BKL → serialized; shared iters[][] writes → MTTCG false sharing). `scripts/smoke-smp-speedup.sh` boots 4 vCPUs under **MTTCG (`-accel tcg,thread=multi`, REQUIRED** — single-threaded TCG round-robins all vCPUs on one host thread so no speedup is measurable) and asserts T(1)/T(4) >= 1.8x + identical checksum. Measured 1345ms→484ms = **2.78x**. Wired into verify64.

**Phase 4 DONE (feat/smp, not pushed) — BKL RETIRED, `make verify64` fully green** (host 738 + BIOS/UEFI/bigmem/e1000e/USB + smoke-smp + speedup ~3-4x + smptorture + nettorture). Audit + phased plan in `docs/superpowers/plans/2026-06-24-bkl-retirement-audit.md` (the original 2-step Task 15 understated it — ~15 BKL-only structures). Built bottom-up: each lock added UNDER the still-present BKL (uncontended), then the BKL flipped off last (15f) and the whole thing re-validated WITHOUT it. SMP documented in `docs/en/x86_64.md` §5.2 (+ PL); ROADMAP Stream C → 🟡 (QEMU). The locks/gates:
- Tasks 11-14: frame alloc, heap, ProcTable (`g_procLock` recursive), DeviceManager, VFS (`g_vfsLock` recursive), BlockCache, JBD2 (`txLock`); real **IPI TLB shootdown** (`smpTlbShootdown` + `smpPollShootdown` polled in every `Spinlock::lock` spin so a CPU spinning for a lock with IRQs off still services a shootdown — the deadlock-safe part). New reusable locks in `kernel/Spinlock.h`: `SpinGuard`/`RecursiveSpinlock`/`RecursiveGuard`/`RecursiveIrqGuard`.
- 15a `g_rqLock` (runqueue): released across `archContextSwitch` like the BKL; the `runningCpu` gate kept verbatim; `onTick` takes it AFTER `tickRealTimers` so the order stays `g_procLock -> g_rqLock`; `reap` split into lock-free `reapLocked` (onTick) + locking `reap` (Exec).
- 15b `Pipe::m_lock`, `g_futexLock` (futex glue, `futexWakeNLocked` for atomic REQUEUE), `Syscalls::m_fdLock` (recursive; guards slot ALLOC/FREE only — read/write act on a stable slot, console read blocks inside the call, concurrent same-fd ops are POSIX-unspecified w/o fd refcounting).
- 15c `g_execLock` (the single 0x800000 staging window + dynloader globals; released before archLoadUser/archEnterUser).
- 15d console sink recursive IRQ lock (benign interleave; recursive so a panic-print on the same CPU nests).
- **Gate built:** `user/smptorture.c` + `scripts/smoke-smp-stress.sh` (`make smoke-smp-stress`, wired into verify64) — 8 threads hammer the fd table (read-only churn vs a reference), a shared pipe (per-id count oracle), signals (survival), a mutex counter (lost-update) under MTTCG. NOTE: signal volume capped at 200/thread — 16000 signals wedged (volume-induced, separate from the locks).

**Benign / documented (single-word or cosmetic, NOT memory-unsafe, gate can't validate):** signal masks (`uint64` SigMask, coalescing, idempotent same-signal posts — 38 delicate touch points, locking risks breaking tested Ctrl+C/job-control), job-control globals (`g_foregroundPid`/`g_consolePgrp`, atomic int). Left for a follow-up.

- 15e net stack: coarse RECURSIVE `g_netLock` (`net/NetLock.h`, defined in Socket.cpp) at the 3 boundaries — every socket* fn, `netRxProcess` (RX-softirq thread), `tcpTick`/`arpTick` (net-timer thread) + `packetRecv`/`tcpSnapshot`; internals nest. Order `m_fdLock -> g_netLock -> g_rqLock`. Gate `nettorture` (UDP loopback ping-pong, 6 threads) drives the RX-softirq thread vs socket syscalls.
- 15f THE FLIP: `bklEnter/bklExit` (C wrappers the asm stubs + usermode call) made NO-OPS in `Bkl.cpp`; the scheduler's direct `g_bkl.enter/exit` removed (`g_rqLock` handoff alone now). No asm edits — trivially reversible. `g_bkl` kept unreferenced one release.

**KEY LEARNINGS:** (1) reused `RecursiveSpinlock` everywhere subsystems compose (VFS/proc/fd/console/net) — a plain lock self-deadlocks on `infoByPid->byPid`, `dup2->close`, `socketPoll->socketReadable`, etc. (2) Can't hold a spinlock across a blocking syscall — console read blocks INSIDE the call (so the fd lock guards slot alloc/free only, not read/write), socket recv blocks at the dispatch layer (so net ops are non-blocking). (3) Signal masks + job-control globals left UNLOCKED: single `uint64`/`int`, benign-coalescing, and the 38 delicate signal-delivery sites risk breaking tested Ctrl+C — documented follow-up, NOT memory-unsafe. (4) Heavy futex/signal/socket VOLUME is pathologically slow under BKL+MTTCG (every wake serializes on the BKL) — the gates use MODEST volume (concurrency, not volume, is what races); pre-existing pthrstress shows the same; should improve post-flip. (5) The stress gates are timing-sensitive under MTTCG — `SETTLE` 150s.

**Follow-ups:** strip the now-no-op `bklEnter/bklExit` calls from the 3 asm stubs (perf); proper signal-state lock; per-inode VFS + per-socket locks (the coarse `g_vfsLock`/`g_netLock` are correctness-first); push feat/smp.
